# Test Plan Template

Use this template when the user asks for a test plan or when a broad testing task starts without a plan. Adapt section names only when the scope is clearly narrower.

Write the plan in Chinese by default. Keep commands, file paths, code ids, and test identifiers in their original form.

The structure below is based on the repository's current effective pattern: define the plan first, assign stable IDs, then execute and update a separate current-state report against those IDs.

## Writing rules

- 先写计划，再开始大范围执行。
- 测试点必须带稳定 ID。
- 每个测试点都要写清楚成功条件和主要证据。
- 计划点的粒度要能直接映射到测试报告中的一行状态。
- 如果执行过程中新增/删减测试点，先改计划，再继续执行。
- 若本轮可能需要唤起外部 worker，先在计划里确认升级策略，不要等失败后才临时约定。
- 如果测试对象涉及 Agent / LLM，计划应说明哪些上下文是复现必需证据，例如 prompt、tool trace、模型版本、环境配置或 session id。

## Design rules

- 优先按设计文档分块来组织测试点，而不是按测试文件分块。
- P0 只保留真正阻塞验收的核心链路。
- “预期结果”不要写成泛化表述，应写可观察结果。
- “主要证据”要能指导后续实际采证，不要写成空泛类别。
